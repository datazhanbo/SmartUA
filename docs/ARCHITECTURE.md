# SmartUA - 系统架构设计文档

## 1. 系统概览

### 1.1 设计理念

> **大模型驱动的第三代投放平台**
>
> - 第一代：媒体控制台（人工操作）
> - 第二代：批量工具+BI报表（半自动化）
> - 第三代：意图驱动+Human-in-the-loop（智能决策）

**核心差异**：

| 维度 | 传统投放平台 | SmartUA 智能投放 |
|------|------------|----------------|
| 操作入口 | 菜单+表单 | 自然语言对话（待实现） |
| 决策主体 | 100%人工 | AI建议 + 人类把关 |
| 自动化能力 | 规则引擎（硬编码） | 意图识别 + 风险评估 + 闭环学习 |
| 安全机制 | 二次确认 | 智能分级 + 超时自动执行 |
| 数据架构 | 单一数据表 | 四层数仓（ODS/DWD/DWS/ADS） |
| 前端Mock | 前端硬编码Mock | 数据库层Demo数据 |

## 2. 核心架构模块

### 2.1 四层运营实体模型 ✅

**设计目标**：Campaign-AdGroup-Ad-Creative 四层结构，与主流媒体平台模型完全对齐

```
┌───────────────────────────────────────────────────────────┐
│                      Campaign (活动)                      │
│  ┌─────────────────────────────────────────────────────┐  │
│  │  id, name, app_id, country, platform, media, dsp    │  │
│  │  budget, bid_strategy, optimization_goal, status    │  │
│  │  health, roi, spend, impressions, clicks, installs     │  │
│  └─────────────────────────────────────────────────────┘  │
└─────────────────────────────┬─────────────────────────────┘
                              │ 1:N
              ┌───────────────▼───────────────┐
              │       AdGroup (广告组)         │
              │  ┌───────────────────────────┐ │
              │  │ id, campaign_id, name...  │ │
              │  │ audience, budget, status  │ │
              │  │ roi, spend, installs...      │ │
              │  └───────────────────────────┘ │
              └───────────────┬───────────────┘
                              │ 1:N
                 ┌────────────▼────────────┐
                 │       Ad (广告)          │
                 │  ┌─────────────────────┐ │
                 │  │ id, adgroup_id...   │ │
                 │  │ creative_id, status  │ │
                 │  │ roi, spend, clicks...│ │
                 │  └─────────────────────┘ │
                 └────────────┬─────────────┘
                              │ N:1
                 ┌────────────▼────────────┐
                 │    Creative (素材)       │
                 │  ┌─────────────────────┐ │
                 │  │ id, type, format... │ │
                 │  │ url, tags, spend...│ │
                 │  └─────────────────────┘ │
                 └──────────────────────────┘
```

**API设计：** Campaign API 返回**嵌套数据结构**，避免前端多次请求

```json
GET /api/v1/campaigns/5
{
  "id": 5,
  "name": "Campaign_US_Android",
  "roi": "2.35",
  "spend": "5000.00",
  "ad_groups": [
    {
      "id": 8,
      "name": "US-Broad-Target",
      "ads": [
        {
          "id": 1,
          "name": "Ad-Creative-A",
          "creative_id": 5
        }
      ]
    }
  ]
}
```

**标准状态流**（所有四层共用）：
```
draft → approved → api_submitted → running → paused → ended
```

### 2.2 前端数值安全渲染机制 ✅

**问题**：SQLAlchemy Decimal 类型 JSON 序列化后为字符串

**解决方案**：前端统一安全处理模式
```javascript
// 所有数值字段处理
const numVal = Number(val)
return !isNaN(numVal)
  ? <span style={{ color: getStatusColor(numVal), fontWeight: 'bold' }}>
      {numVal.toFixed(2)}
    </span>
  : <span style={{ color: '#999' }}>-</span>
```

**应用场景**：
- ROI、Spend、CPI、CTR、Impressions、Clicks、Installs
- 所有表格列、统计卡片、详情展示

### 2.3 告警系统 ✅

```
┌──────────────────────────────────────────────────────────┐
│  告警检测流水线                                           │
│  ┌──────────────────────────────────────────────────┐  │
│  │  1. ROI 下降检测 (连续3天下降超过阈值)          │  │

│  │  3. 花费异常检测 (较昨日下降超过阈值)            │  │
│  │  4. CTR 异常检测 (骤降/骤升)                     │  │
│  └──────────────────────────────────────────────────┘  │
│                          ↓                              │
│  ┌──────────────────────────────────────────────────┐  │
│  │  风险等级评估                                     │  │
│  │  ├─ HIGH: 影响 ≥$5000/天 或 ROI下降≥30%        │  │
│  │  └─ MEDIUM: 影响 <$5000/天                      │  │
│  └──────────────────────────────────────────────────┘  │
│                          ↓                              │
│  ┌──────────────────────────────────────────────────┐  │
│  │  建议动作生成                                     │  │
│  │  ├─ 降低出价 X%                                │  │
│  │  ├─ 检查素材表现                               │  │
│  │  └─ 暂停低ROI广告组                             │  │
│  └──────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

### 2.4 操作安全分级矩阵（待实现）

| 风险等级 | 人机交互模式 | 审批要求 | 超时策略 | 典型操作场景 |
|---------|------------|---------|---------|------------|
| **L0** | Human-on-the-loop | 无需审批 | 立即执行 | 素材轮换、告警检查、报表生成 |
| **L1** | 一键确认 | 可选审批 | 10分钟超时自动执行 | 暂停低ROI Campaign<br>预算调整±20% |
| **L2** | Human-in-the-loop | 必须审批 | 不自动执行 | 提价>50%<br>单日提额>$1000 |
| **L3** | 仅建议 | 完全人工 | 永不自动 | 新建Campaign<br>大策略调整 |

## 3. 前端架构 ✅

### 3.1 页面结构

```
App.jsx (路由层)
├── /login              # 登录页
├── /dashboard          # 投放大盘

│   │   ├── ROI趋势图
│   │   └── AdGroup列表
│   ├── Tab2: AdGroup详情
│   │   ├── AdGroup统计
│   │   └── Ad列表表格
│   ├── Tab3: 广告创意
│   │   └── 创意卡片网格
│   │   └── 素材优化按钮
│   │   └── 暂停广告按钮
│   └── Tab4: 设置
│       └── Campaign配置详情
└── /creatives          # 素材管理
    ├── 统计卡片 (4个)
    ├── 素材筛选 (支持按类型/设计师/状态过滤)
    └── 素材详情弹窗
```

### 3.2 前端核心组件设计原则

1. **无Mock数据原则**：前端不硬编码任何模拟数据
   - 所有数据来自后端API
   - Demo数据仅存在于数据库初始化层

2. **空状态友好**：所有列表、表格、详情页都处理空状态
   - 草稿状态（Draft Campaign（无数据时展示友好提示

3. **数值安全**：所有数值渲染都经过 `Number()` + `isNaN()` 检查
   - 避免 `null/`undefined`/`NaN` 统一显示为 `-`

4. **状态一致性**：所有四层实体共用同一套状态标签颜色体系

## 4. 后端API架构 ✅

### 4.1 API分层设计

```
HTTP Request
    ↓
FastAPI Route Layer (route handlers)
    ↓
Pydantic Schema Layer (request/response validation)
    ↓
SQLAlchemy Model Layer (DB operations)
    ↓
SQLite / PostgreSQL
```

### 4.2 核心API端点

```python
# Auth API
POST   /api/v1/auth/login          # JWT登录
GET    /api/v1/auth/me             # 当前用户信息

# Campaign API (嵌套返回)
GET    /api/v1/campaigns            # 列表
GET    /api/v1/campaigns/{id}      # 详情（含ad_groups.ads）

# AdGroup API
GET    /api/v1/campaigns/{id}/adgroups
GET    /api/v1/adgroups/{id}/ads

# Creative API
GET    /api/v1/creatives            # 列表
GET    /api/v1/creatives/{id}     # 详情

# Data API
GET    /api/v1/data/alerts          # 告警列表
POST   /api/v1/data/alerts/{id}/resolve
```

### 4.3 数据库初始化流水线

```
init_db.py
    ↓
1. 创建所有表
    ↓
2. 插入系统数据（Users/Roles/Permissions）
    ↓
3. 插入App数据（Block Blast / Mahjong Master）
    ↓
4. 插入Campaign → AdGroup → Ad → Creative 层级Demo数据
    ↓
5. 初始化告警数据（init_alerts.py）
    ↓
完成 ✅ 可直接启动使用
```

## 5. 多租户与权限模型 ✅

### 5.1 RBAC权限模型

```
Permission → Role → User
    ↓         ↓
  Menu      User-App Binding
```

**权限粒度**：
- **菜单权限**：哪些角色能看到哪些页面
- **操作权限**：read / write / approve / execute
- **数据权限**：能看到哪些App的数据
- **字段权限**：敏感字段的可见性控制

**预定义角色**：

| 角色 | 说明 | 权限 |
|------|------|------|
| admin | 管理员 | 所有权限 |
| optimizer | 优化师 | 查看+操作投放 |
| analyst | 分析师 | 仅查看数据 |
| finance | 财务 | 仅查看花费/ROI |

## 8. 数据模型ER图

### 8.1 核心实体关系 ✅

```
┌─────────────┐       ┌─────────────┐       ┌─────────────┐
│     App     │       │    User     │       │    Role     │
└──────┬──────┘       └──────┬──────┘       └─────────────┘
       │                     │
       │ 1:N                 │ 1:N
       ▼                     ▼
┌─────────────┐       ┌─────────────┐
│  Campaign   │       │ UserAppBind │
└──────┬──────┘       └─────────────┘
       │ 1:N
       ▼
┌─────────────┐
│   AdGroup   │
└──────┬──────┘
       │ 1:N
       ▼
┌─────────────┐       ┌─────────────┐
│     Ad      │──────▶│  Creative   │
└─────────────┘  N:1  └─────────────┘
```

### 8.2 字段设计要点

**Campaign 关键字段**：
- `media`: 媒体平台（Meta/Google/TikTok）
- `dsp`: DSP/广告账户
- `bid_strategy`: 出价策略
- `optimization_goal`: 优化目标
- `health`: 健康度（excellent/good/warning/danger/pending
- `status`: 状态（running/paused/draft/ended/api_submitted

**Creative 关键字段**：
- `type`: 类型（video/image/playable/carousel）
- `format`: 文件格式（mp4/jpg/png/html）
- `tags`: 标签数组（设计师、风格、版本等）
- `performance_score`: 表现分 0-100
- `trend`: 趋势（up/down/stable）
